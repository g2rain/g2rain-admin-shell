# v1.0.0 · G2rain（谷雨）Admin Main Shell

本版本准备 `g2rain-admin-shell` 的首个 GHCR 镜像发布流程。G2rain（谷雨）是面向企业的开源智能体平台，连接模型、知识与业务工具；平台现有 SaaS 基座、知识库和应用开发/部署能力可用，智能体平台与智能客服已开发完成并开源，交易、订阅和计量计费仍处于规划设计阶段。`g2rain-admin-shell` 仅是该平台中的 Vue 主应用模板/浏览器入口基线，负责全局布局、导航、工作区、会话协调和可信微应用承载；它不单独提供平台的业务、知识、智能体、IAM 或网关能力。平台总体能力和开放状态以 [G2rain 主仓库](https://github.com/g2rain/g2rain) 为准。

## 本次交付

- 根目录 `Dockerfile` 与 `build.sh` 复用同一 Vue 构建和 OpenResty 运行镜像；运行时入口为 `/docker-entrypoint.sh`，容器监听 `8080`。
- GitHub Actions 只在推送精确格式 `v<major>.<minor>.<patch>` 的 Git tag 时执行。它校验 tag 在 `origin/main` 历史中、同名发布说明存在且非空、并与 `package.json` 版本一致，然后执行 `npm ci` 与 `npm run build`。
- 通过 GitHub 自动提供的 `GITHUB_TOKEN` 推送 `ghcr.io/g2rain/g2rain-admin-shell:1.0.0` 与 `ghcr.io/g2rain/g2rain-admin-shell:sha-<完整提交 SHA>`；不创建 GitHub Release、不部署、不更新 `latest`。OCI 元数据包含源仓库、标题、描述、版本、提交和 `Apache-2.0` 许可证。

## 构建、镜像与运行要求

项目版本事实源为 `package.json`（并同步到 `package-lock.json` 和 `docs/project.yaml`），当前为 `1.0.0`。要求 Node.js `>= 22` 与 npm；`npm run build` 运行 TypeScript 类型检查和 Vite 生产构建。本仓没有独立的 `test` 脚本，因此 CI 的完整自动验证范围是锁定依赖安装、类型检查和生产静态构建，而不是浏览器、容器运行或实际部署验收。

镜像构建使用 Node `22-alpine`，最终运行时是 `openresty/openresty:alpine`。最终镜像包含 `dist/` 静态资源、`lua/sign.lua`、`lua/sign_api.lua`、`lua/config.lua`、Nginx 配置模板、启动脚本以及 `lua/keys/README.md`；密钥目录只创建为空目录。镜像中的 Lua 签名能力要求在生产运行时以只读 volume/secret 挂载 `private-key.der`、`public-key.der`、`iam-key-id.txt` 和 IAM 公钥 PEM，绝不可烘焙进镜像或提交到 Git。

根目录已跟踪 `.env` 包含开发上游地址，虽不是 Token 或密钥，也不应被视为可公开生产配置。它现已排除于 Docker 构建上下文，但这不会改变其 Git 可见性；维护者应在公开源码前独立评估该地址是否应保留。`.env.production` 是构建所需的运行时占位符，`SSO_BASE_URL` 由容器启动时写入 `env-config.js`；生产真实值通过环境变量/部署系统注入。

## 发布顺序与可见性

本仓分支流程是 `feature/* → develop → main`。先将本发布说明、版本和工作流按该流程合入 `main`，在经过验证的 `main` 提交创建并推送 `v1.0.0`；只有此后 Actions 成功推送两个标签才算镜像发布成功。

首次成功推送后，如需匿名拉取，进入 GitHub Packages 的包页面：**Package settings → Change visibility → Public**。若组织管理员禁止修改，请联系管理员。若 GHCR 返回 `denied`，除检查组织 Packages 策略外，还应在已有包的 **Package settings → Actions access** 中向 `g2rain-admin-shell` 授予写权限；`packages: write` 工作流权限本身不能保证已有包允许写入。

## 验证状态与已知限制

本次发布准备应在本地执行 `npm ci` 与 `npm run build`；容器构建、镜像文件检查、GHCR 推送、匿名拉取和实际部署需要分别记录实际结果，不能由静态构建或 Actions 配置推断。真实 IAM/Gateway/签名联调、生产微路径刷新回退和运行时密钥注入的验收仍需目标环境完成。Token 本地持久化及同页 Auth Bridge 风险与退出条件见[已知偏差](../architecture/deviations.md)。本仓使用标准 [Apache License 2.0](../../LICENSE)，包元数据与 OCI 许可证标签均为 `Apache-2.0`。
